# 아이템 조합 분석기

## 개요

1라운드에서 받은 조합 아이템으로 어떤 완성 아이템을 만드는 것이 승률이 높은지 통계로 분석

## 핵심 로직

### 입력
- 조합 아이템 선택 (**최대 4개**, 중복 가능)
- 예: 대검, 곡궁, 갑옷, 망토

> **4개 제한 이유**: 1라운드에서 일반적으로 받는 조합템 개수 기준

### 처리 과정

#### 1단계: 가능한 완성 아이템 조합 계산

선택한 조합 아이템으로 만들 수 있는 완성 아이템의 **모든 경우의 수** 계산

```
입력: 대검, 곡궁, 갑옷

가능한 조합:
1. 거인학살자(대검+곡궁) + 갑옷 남음
2. 수호천사(대검+갑옷) + 곡궁 남음
3. 유령무희(곡궁+갑옷) + 대검 남음
```

#### 2단계: 각 조합별 통계 계산 (남은 아이템 기반 분류)

**핵심**: 같은 완성 아이템이라도 **남은 조합 아이템**에 따라 별도 통계로 분류

```
예시: 구인수의 격노검을 만들 수 있는 경우

입력 1: 곡궁, 장갑, 갑옷
→ 구인수(곡궁+장갑) + 갑옷 남음 → 평균 4.2등

입력 2: 곡궁, 장갑, 대검
→ 구인수(곡궁+장갑) + 대검 남음 → 평균 3.8등
```

**이유**: 남은 아이템에 따라 다음에 만들 수 있는 아이템이 달라지므로 플레이 방향과 승률이 달라짐

DB에서 해당 완성 아이템 + 남은 조합템 조건을 만족하는 게임들을 필터링하여 통계 계산

#### 3단계: 상세 게임 정보 제공

각 조합별로 **최대 10게임**의 상세 정보 표시:
- 덱 구성 (챔피언 목록)
- 전체 아이템 조합
- 최종 순위

### 출력 형태

```
분석 결과 (총 120게임 분석)

#1 거인학살자(대검+곡궁) + 갑옷 남음
   평균 3.2등 | 상위4 72% | 45게임

   [상세 보기]
   ├─ 1등: 진, 자야, 트위치... | 거인학살자, 구인수, 피바라기
   ├─ 2등: 녹턴, 렝가... | 거인학살자, 무한의대검, 최속
   └─ ... (최대 10게임)

#2 수호천사(대검+갑옷) + 곡궁 남음
   평균 3.8등 | 상위4 65% | 38게임
   ...

#3 유령무희(곡궁+갑옷) + 대검 남음
   평균 4.1등 | 상위4 58% | 37게임
   ...
```

### 통계 필터링 로직

```
조건 1: 완성 아이템 보유
- 플레이어가 해당 완성 아이템을 보유했는지 확인

조건 2: 남은 조합 아이템으로 만들 수 있는 완성 아이템 보유 (선택적)
- 남은 조합템이 있는 경우, 그 조합템으로 만들 수 있는
  완성 아이템 중 하나라도 보유했는지 확인
- 이를 통해 "비슷한 빌드 경로"의 게임만 필터링

예시:
입력: 대검, 곡궁, 갑옷
조합: 거인학살자(대검+곡궁) + 갑옷 남음

필터링 조건:
1. 거인학살자 보유 AND
2. (갑옷으로 만들 수 있는 아이템 중 하나 보유)
   - 수호천사, 선파이어, 가시갑옷, 적응형, 승천의 갑옷 등
```

## 데이터 수집

### 수집 방식

```
챌린저 상위 200명
    ↓
각 플레이어의 최근 20게임 수집 (Riot API)
    ↓
1게임 = 8명 플레이어 데이터 저장
```

### 데이터 규모

| 항목 | 설명 |
|------|------|
| tft_matches | 매치 정보 (1게임 = 1레코드) |
| tft_players | 플레이어 정보 (1게임 = 8레코드) |
| 총 레코드 | 약 16,000~20,000개 (플레이어 데이터) |
| 실제 매치 수 | 레코드 수 ÷ 8 |

> **참고**: UI에 표시되는 "X개 플레이어 데이터 기반"은 `tft_players` 테이블의 레코드 수입니다.

## 데이터 구조

### DB 테이블: tft_players

```sql
- placement: 최종 순위 (1~8)
- units: JSON 배열
  - character_id: 챔피언 ID
  - itemNames: 완성 아이템 API 이름 배열
  - tier: 성급
```

### 아이템 매핑

- 조합 아이템: "BFSword", "RecurveBow", "ChainVest" 등 (문자열)

- 조합 레시피: ITEM_RECIPES 객체에 정의

## 아이템 이미지 표시

### 이미지 소스

**Data Dragon (Riot 공식 CDN)** 사용

```
URL 패턴:
https://ddragon.leagueoflegends.com/cdn/{version}/img/tft-item/{itemApiName}.png

예시:
- 대검: https://ddragon.leagueoflegends.com/cdn/15.24.1/img/tft-item/TFT_Item_BFSword.png
- 무한의 대검: https://ddragon.leagueoflegends.com/cdn/15.24.1/img/tft-item/TFT_Item_InfinityEdge.png
- Set16 엠블럼: https://ddragon.leagueoflegends.com/cdn/15.24.1/img/tft-item/TFT16_Item_BilgewaterEmblemItem.png
```

### 적용 위치

1. **조합 아이템 선택 버튼**: 이모지 → 아이템 이미지
2. **선택된 아이템 표시**: 텍스트 옆에 아이템 이미지
3. **결과 카드**: 완성 아이템 이름 옆에 이미지
4. **남은 조합 아이템**: 조합템 이미지 표시
5. **샘플 게임 아이템 목록**: 아이템 이미지로 표시

### 이미지 URL 생성

```typescript
// src/lib/itemImage.ts

const DDRAGON_VERSION = "15.24.1";
const DDRAGON_BASE = "https://ddragon.leagueoflegends.com/cdn";

// 완성 아이템 이미지 (TFT_Item_xxx 형태)
export function getItemImageUrl(itemApiName: string): string {
  return `${DDRAGON_BASE}/${DDRAGON_VERSION}/img/tft-item/${itemApiName}.png`;
}

// 조합 아이템 이미지 (BFSword → TFT_Item_BFSword)
export function getComponentImageUrl(componentId: string): string {
  return `${DDRAGON_BASE}/${DDRAGON_VERSION}/img/tft-item/TFT_Item_${componentId}.png`;
}
```

### 요구사항 1: 최소 선택 개수 변경

**변경 전**: 최소 1개 ~ 최대 4개
**변경 후**: 최소 2개 ~ 최대 4개

**이유**: 1라운드 초반에 최소 2개의 조합 아이템은 얻기 때문

**영향 범위**:
- UI: 분석 버튼 disabled 조건 (1개 → 2개)
- UI: 안내 문구 수정

---

### 요구사항 2: 완성아이템 2개 조합 통계

**현재 동작** (4개 선택 시):
```
입력: 대검, 지팡이, 벨트, 눈물

결과:
- 마법공학 총검(대검+지팡이) + [벨트, 눈물] 남음
- 스테락의 도전(대검+벨트) + [지팡이, 눈물] 남음
- 대천사의 지팡이(지팡이+눈물) + [대검, 벨트] 남음
```

**추가할 동작**:
```
입력: 대검, 지팡이, 벨트, 눈물

결과 (기존 + 추가):
- 마법공학 총검 + [벨트, 눈물] 남음
- **마법공학 총검 + 정령의 형상** ← 추가 (벨트+눈물로 완성)
- 스테락의 도전 + [지팡이, 눈물] 남음
- **스테락의 도전 + 대천사의 지팡이** ← 추가 (지팡이+눈물로 완성)
- 대천사의 지팡이 + [대검, 벨트] 남음
- **대천사의 지팡이 + 스테락의 도전** ← 추가 (대검+벨트로 완성)
```

**로직**:
1. 남은 조합 아이템이 정확히 2개인 경우
2. 그 2개로 만들 수 있는 완성 아이템이 있으면
3. "첫번째 아이템 + 두번째 아이템" 조합으로 별도 통계 생성

**API 응답 변경**:
```typescript
interface CombinationResult {
  mainItem: string;
  mainItemName: string;
  secondItem?: string;        // 추가: 두 번째 완성 아이템
  secondItemName?: string;    // 추가
  usedComponents: string[];
  remainingComponents: string[];  // 2개 아이템 조합이면 빈 배열
  // ...
}
```

### 2024-12-28: 데이터 중복 카운트 버그

**증상**: 4개 조합 아이템 선택 시, "완성+완성" 케이스가 항상 "완성+조합2개"보다 상위에 표시됨

**원인**: 두 케이스에 동일한 플레이어가 중복으로 카운트됨

```
예시: 대검+활+갑옷+망토 선택

[버그 발생 시]
Case 1 (크라켄 + [갑옷,망토]):
  - 조건: 크라켄 보유 AND (갑옷/망토로 만든 아이템 보유)
  - 포함 대상: 크라켄+용의 발톱 보유 플레이어 ✓

Case 2 (크라켄 + 용의 발톱):
  - 조건: 크라켄 보유 AND 용의 발톱 보유
  - 포함 대상: 크라켄+용의 발톱 보유 플레이어 ✓

→ 같은 플레이어가 양쪽에 중복 카운트!
→ Case 1의 평균이 Case 2 데이터로 "희석"됨
```

**해결**: Case 1에서 Case 2에 해당하는 플레이어를 제외

```typescript
// route.ts 수정 내용

if (remainingComponents.length === 2) {

// Case 1 필터링 시 제외 조건 추가
if (exactSecondItem && hasItem(player.units, exactSecondItem)) {
  continue;  // Case 2 해당자는 Case 1에서 제외
}
```

```
3위  | 거인 학살자 + [갑옷,망토]  | 4.37등   | 완성+조합
```

### 2024-12-28: 거인 학살자 상세 분석

**스크립트**: `scripts/analyze-giant-slayer-detail.js`

**발견**: 가고일 돌갑옷이 거인 학살자와 시너지가 없는 약한 조합

| 조합 | 평균 등수 | vs 가고일 |
|------|----------|----------|

**원인 분석**:
1. 거인 학살자 = 공격템 (캐리용)
2. 가고일 돌갑옷 = 순수 방어템 (탱커용)

**최종 결론**:
- "완성+완성 vs 각각활용" 자체의 차이가 아님
- **특정 아이템 조합의 시너지** 문제
- 시너지 좋은 조합(밤의 끝자락+라바돈) → 완성+완성이 좋음
- 시너지 나쁜 조합(거인 학살자+가고일) → 각각활용이 좋음

### 2024-12-28: 필터링 편향 문제 발견 및 방안 2 적용

**문제**: 완성+완성 vs 각각활용 비교에서 숨겨진 선택 편향 존재

| 지표 | 완성+완성 | 각각활용 |
|------|----------|---------|

| **평균 아이템** | **12.64개** | **10.88개** |

**근본 원인**:
```
완성+완성 필터: "A아이템 + B아이템 동시 보유"
  → 특정 2개 아이템을 동시에 갖는 까다로운 조건
  → 아이템이 많을수록 조건 충족 확률 증가

각각활용 필터: "A아이템 + 아무 벨트템 + 아무 활템 + B아이템 미보유"
  → 넓은 범위의 아이템 조건 (충족 쉬움)
  → "B 미보유" 조건은 아이템 적을수록 유리
```

**결론**: "완성+완성이 더 좋다"가 아니라 **필터 조건으로 인한 선택 편향**

**해결: 방안 2 (비교 로직 폐기)**

```
- 최후의 속삭임 - 4.5등
```

**변경 후 (v3)**:
```
입력: 지팡이, 곡궁, 장갑, 망토

결과 (2개 아이템 조합):
- 구인수 + 수은 - 4.3등 (지팡이+곡궁 + 장갑+망토)
```

**조합 생성 알고리즘**:
```
입력: [A, B, C, D] (4개 조합 아이템)

1. 첫 번째 아이템 후보:
   - A+B로 만들 수 있는 완성 아이템
   - A+C로 만들 수 있는 완성 아이템
   - A+D로 만들 수 있는 완성 아이템
   - B+C로 만들 수 있는 완성 아이템
   - B+D로 만들 수 있는 완성 아이템
   - C+D로 만들 수 있는 완성 아이템

2. 각 첫 번째 아이템에 대해:
   - 남은 2개 조합으로 만들 수 있는 두 번째 아이템 확인
   - (첫번째 아이템, 두번째 아이템) 쌍 생성

3. 중복 제거:
   - (A, B)와 (B, A)는 같은 조합 → 하나만 유지
```

---

### 요구사항 2: 3개 선택 시 남은 조합 구분

**기존 (방안 2)**:
```
입력: 지팡이, 곡궁, 벨트

결과 (개별 아이템별):
- 구인수의 격노검 - 4.5등
- 마법공학 총검 - 4.4등
- 내셔의 이빨 - 4.6등
```

**변경 후 (v3)**:
```
입력: 지팡이, 곡궁, 벨트

결과 (완성 + 남은 조합):
- 구인수 + 벨트 - 4.4등 (지팡이+곡궁, 벨트 남음)
- 마법공학 총검 + 곡궁 - 4.5등 (지팡이+대검???... 아, 대검이 없네)
  → 조합 불가능한 경우는 제외
- 내셔 + 지팡이 - 4.6등 (곡궁+벨트, 지팡이 남음)
```

**핵심 로직**:
1. 3개 조합 아이템에서 2개를 선택하여 완성 아이템 생성
2. 남은 1개 조합 아이템에 따라 **별도 통계** 계산
3. 같은 완성 아이템이라도 남은 조합이 다르면 다른 케이스

**예시**:
```
입력: 곡궁, 장갑, 벨트

Case A: 최후의 속삭임(곡궁+장갑) + 벨트 남음
Case B: 내셔의 이빨(곡궁+벨트) + 장갑 남음
Case C: 타격대의 철퇴(벨트+장갑) + 곡궁 남음

→ Case A와 Case B는 다른 통계!
→ 남은 조합 아이템으로 다음에 만들 수 있는 아이템이 다르기 때문
```

**필터링 조건**:
```
Case A 필터:
- 최후의 속삭임 보유
- (벨트로 만들 수 있는 아이템 중 하나 보유) 또는 벨트 자체 보유
  → 선택적: 더 정확한 통계를 위해 적용 여부 결정
```
