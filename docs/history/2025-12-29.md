# 2025-12-29 세션 기록

## 요약
- MetaTFT 사이트 구조 분석 (기획적 관점)
- TFT 조합 분류 방식 연구 (K-means 클러스터링)
- 신규 기능 아이디어: 초반 보드 → 최종 덱 추천기

## 주요 결정사항

### MetaTFT 분석 결과
1. **플랫폼 구성**: 웹사이트 + Overwolf 데스크톱 앱
2. **핵심 기능**: Comps, Items, Augments, Units, Tier Lists
3. **데이터 규모**: 매일 200만+ 게임 분석, 5분마다 업데이트
4. **수익 모델**: 무료 + 프리미엄 구독

### TFT 조합 분류 방식
1. **K-means 클러스터링**: 최종 보드를 벡터화하여 유사한 조합 그룹화
2. **챔피언 벡터**: 각 게임을 [챔피언1 유무, 챔피언2 유무, ...] 형태로 변환
3. **거리 계산**: 챔피언 구성이 유사하면 같은 클러스터로 분류
4. **이름 부여**: 클러스터 내 공통 특성 분석 (예: 필트오버 6+ → "6필트오버")

### 신규 기능 아이디어: 덱 추천기
**사용자 요청**:
> 챌린저 랭크 게임 다수 수집 → 유저가 초반 단계에서 자신의 덱 구성과 아이템 보유 현황 그리고 증강을 입력 → 이 상황에서 갈만한 덱을 추천해줌

**핵심 발견 - Riot API 한계**:
- Riot API는 **최종 게임 상태만** 제공
- 라운드별/스테이지별 보드 상태는 제공하지 않음
- MetaTFT는 Overwolf 앱으로 실시간 데이터 캡처하여 해결

**구현 가능한 방법**:

| 접근법 | 실현 가능성 | 정확도 | 개발 난이도 |
|--------|------------|--------|------------|
| Overwolf 앱 | 가능 (데스크톱) | 매우 높음 | ★★★★★ |
| **규칙 기반 추천** | ✅ 즉시 가능 | 중간~높음 | ★★☆☆☆ |
| 하이브리드 | ✅ 가능 | 높음 | ★★★☆☆ |

**추천 접근법: 규칙 기반 + Riot API 하이브리드**

```
[사용자 입력]
- 현재 보유 챔피언 (예: 바이, 세라핀, 자이라)
- 보유 아이템/조합재료 (예: BF검, 곡궁)
- 선택한 증강 (예: 필트오버 문장)

[추천 로직]
- 메타 조합 템플릿과 매칭률 계산
- 챔피언 매칭 50% + 아이템 적합도 30% + 증강 시너지 20%
- Riot API로 각 조합의 실제 평균 등수 표시

[출력]
- 추천 1: 6필트오버 (매칭도 95%) - S티어
- 추천 2: 4아르카나 (매칭도 60%) - A티어
```

**데이터 구조 설계**:
```typescript
interface CompTemplate {
  name: string;                    // "6필트오버 징크스"
  coreChampions: string[];         // 필수 챔피언 (90%+ 등장)
  flexChampions: string[];         // 유동 슬롯
  coreSynergies: SynergyRequirement[];
  coreItems: ItemBuild[];
  goodAugments: string[];
  tier: 'S' | 'A' | 'B' | 'C';
  avgPlacement: number;            // API 데이터
}
```
