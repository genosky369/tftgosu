### DPS 계산기 폐기

**폐기 사유**: 구인수의 격노검, 거인학살자 등 특수 아이템의 시간 기반 시뮬레이션 구현 시 복잡도가 과도하게 증가

**주요 문제점**:
1. **성능 리스크**: 정적 계산 → 시간 기반 시뮬레이션 전환 시 계산량 20배 증가 (12,000개 조합 × 15~30회 루프)
2. **아키텍처 복잡도**: 특수 아이템 조합별 분기 처리 폭발
3. **정확도 불확실**: 실제 게임과의 검증 어려움 (틱 레이트, 스택 타이밍 등)
4. **유지보수 부담**: 향후 아이템 추가 시 복잡도 기하급수적 증가

**구현 시도 내역**:
- MVP 구현 완료 (기본 DPS 계산, 4개 디버프, 공격자/방어자 관점 전환, 챔피언 한글명)
- 구인수/거인학살자 시간 기반 시뮬레이션 구현 시도
- 리스크 분석 후 폐기 결정

## 아이템 조합 분석기 (세션 2)

### 기능 개요

1라운드에서 받은 조합 아이템으로 어떤 완성 아이템을 만드는 것이 승률이 높은지 통계로 분석하는 기능.

### 핵심 로직

**입력**: 조합 아이템 선택 (최대 6개, 중복 가능)
- 예: 대검, 곡궁, 갑옷

**처리 과정**:
1. 선택한 조합 아이템으로 만들 수 있는 완성 아이템의 **모든 경우의 수** 계산
2. 각 경우의 수별로 DB에서 해당 아이템을 가진 게임 필터링
3. 통계 계산 (평균 등수, 상위4 비율)
4. 샘플 게임 정보 제공 (최대 10개, 덱 구성/아이템)

**출력 예시**:
```
#1 거인학살자(대검+곡궁) + 갑옷 남음
   평균 3.2등 | 상위4 72% | 45게임
   [샘플 게임 보기]
   └ 1등: Jinx, Zaya, Twitch... | 거인학살자, 구인수, 피바라기

#2 수호천사(대검+갑옷) + 곡궁 남음
   평균 3.8등 | 상위4 65% | 38게임
```

### 구현/변경된 파일

| 파일 | 설명 |
|------|------|
| `src/data/item-components.ts` | 아이템 레시피 데이터 (문자열 API 이름 기반) |
| `src/app/api/stats/item-analysis/route.ts` | 통계 계산 API (경우의 수 로직) |
| `src/app/simulator/item-analysis/page.tsx` | UI 페이지 (샘플 게임 표시) |
| `src/config/simulators.ts` | 아이템 분석기 카드 추가 |
| `docs/features/item-analysis.md` | 기능 문서화 |

### 데이터 수집

- **Riot API** 사용 (Development Key)
- 챌린저 50명의 최근 게임 데이터 수집

1. **아이템 ID**: 숫자 ID가 아닌 문자열 API 이름 사용 (`TFT_Item_xxx`)

   - 남는 조합 아이템도 함께 반환

3. **UI 확장**: CombinationCard 컴포넌트
   - 메인 아이템 + 남은 조합 아이템 표시
   - 샘플 게임 접기/펼치기 기능

## 통계 편향 문제 해결 (세션 4)

### 문제 발견

모든 아이템의 평균 등수가 4.5 **미만**으로 표시됨 (4.15 ~ 4.36등)

예: 붉은 덩굴정령 4.15등, 도적의 장갑 4.17등, 구인수 4.36등...

→ 좋은 아이템도 나쁜 아이템도 모두 4.5 이하? 이상함!

### 원인 분석

**높은 등수 플레이어가 더 많은 아이템을 보유**

```
1등: 9개 아이템 → 9개 통계에 각각 등장
8등: 3개 아이템 → 3개 통계에만 등장
```

수학적으로:
```
아이템 인스턴스: 9+8+7+6+5+4+4+3 = 46개
1등 비율: 9/46 = 19.5%
8등 비율: 3/46 = 6.5%

예상 평균: (1×9 + 2×8 + ... + 8×3) / 46 = 3.72등
```

→ 이로 인해 **모든 아이템**이 자연스럽게 4.5 이하로 편향됨

### 해결: 가중치 적용

아이템 개수에 반비례하는 가중치:
- 9개 보유: 1/9 가중치
- 3개 보유: 1/3 가중치

```typescript
const itemCount = countCompletedItems(player.units);
const weight = 1 / itemCount;

// 가중 평균
avgPlacement = weightedSum / totalWeight;
```

### 수정 결과

| 아이템 | 수정 전 | 수정 후 |
|--------|---------|---------|
| 밤의 끝자락 | ~4.1등 | 4.27등 (좋음) |
| 거인 학살자 | ~4.2등 | 4.40등 (좋음) |
| 죽음의 검 | ~4.2등 | 4.51등 (평균) |
| 대천사의 지팡이 | ~4.3등 | **4.59등** (나쁨) |
| 구인수의 격노검 | ~4.3등 | **4.69등** (나쁨) |

→ 이제 좋은 아이템 < 4.5 < 나쁜 아이템 으로 정상 분포!

**변경 파일:**
- `src/app/api/stats/item-analysis/route.ts`: `countCompletedItems()`, 가중 평균 로직 추가

## 이미지 로드 실패 문제 해결 (세션 8)

### 문제 발생

일부 아이템 이미지가 깨져서 표시됨:
- 유형 1: "TF" 텍스트로 노출 (alt 텍스트 일부)
- 유형 2: 빈칸으로 표시

### 원인 분석

**DB에서 반환되는 아이템 유형:**

| 유형 | 예시 | Data Dragon URL | 결과 |
|------|------|-----------------|------|
| 일반 아이템 | `TFT_Item_InfinityEdge` | 존재함 | ✅ 정상 |
| 특수 아이템 | `TFT_Item_ForceOfNature` | 존재함 | ✅ 정상 |
| **Set16 엠블럼** | `TFT16_Item_IxtalEmblemItem` | **없음** | ❌ 403 에러 |

**근본 원인:**
- Set 16 엠블럼 아이템은 `TFT16_Item_` 접두사 사용
- Data Dragon CDN에는 이 이미지가 존재하지 않음

### 해결 방법

`ItemImage` 컴포넌트 생성 (fallback 처리):

```typescript
function ItemImage({ src, alt, width, height, className }) {
  const [hasError, setHasError] = useState(false);

  if (hasError) {
    return (
      <div className="bg-gray-600 flex items-center justify-center text-[8px] text-gray-400"
           style={{ width, height }} title={alt}>
        ?
      </div>
    );
  }

  return (
    <Image src={src} alt={alt} width={width} height={height}
           className={className} unoptimized
           onError={() => setHasError(true)} />
  );
}
```

### 프로세스 개선

`CLAUDE.md`에 "외부 API/CDN 연동 검증 프로세스" 섹션 추가:

1. **URL 패턴 검증**: 기본 케이스 HTTP 요청 테스트
2. **데이터 다양성 검증**: 실제 DB 데이터 샘플링으로 특수 케이스 발견
3. **Fallback 처리 구현**: onError 핸들러 + placeholder UI

### 교훈

- 외부 리소스 연동 시 "URL 패턴이 맞을 것"이라고 가정하지 말 것
- 실제 DB/API 응답 데이터를 샘플링하여 다양한 케이스 확인
- 이미지 로드 실패 시 graceful degradation 필수
