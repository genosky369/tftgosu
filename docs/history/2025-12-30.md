## 주요 결정사항

### 메타 조합 티어리스트 구현

**구현 완료 항목:**
1. K-means 클러스터링 스크립트 (`scripts/analyze-meta-comps.js`)
2. 타입 정의 (`src/types/meta.ts`)
3. API 엔드포인트 (`src/app/api/meta/comps/route.ts`)
4. UI 컴포넌트:
   - `MetaCompCard.tsx` - 덱 카드 (접기/펼치기)
   - `PlacementHistogram.tsx` - 등수 분포 히스토그램
   - `ItemPriorityList.tsx` - 아이템 우선순위 목록
5. 메인 페이지 (`src/app/meta/page.tsx`)
6. 네비게이션 연결 (Header.tsx 수정)

**핵심 기능:**
- 챌린저 게임 데이터 K-means 클러스터링 (k=30)
- 클러스터별 자동 이름 생성 (예: "6필트오버 징크스")
- 아이템 우선순위 계산 (완성 + 재료 아이템)
- 등수 분포 히스토그램 시각화
- 티어 분류 (S/A/B/C)

**설정:**
- 최소 표본: 200게임
- 티어 기준: S(3.5등 이하), A(4.0등 이하), B(4.3등 이하), C(그 외)
- 아이템 점수: 40% delta + 30% 픽률 + 30% 표본

## 중요 교훈: 더미 데이터 사용 정책

### 발생한 문제
- UI 테스트용 더미 데이터에 "6필트오버 징크스"라는 조합을 넣음
- **징크스는 자운 챔피언이지 필트오버가 아님** → 완전히 틀린 정보
- 사용자(TFT 전문가)가 즉시 발견

### 원인
1. `SUPABASE_SERVICE_ROLE_KEY` 없어서 실제 분석 불가
2. UI 테스트를 위해 더미 데이터 생성
3. TFT 메타 지식 없이 "그럴듯해 보이는" 조합 임의 생성
4. 더미 데이터임을 명확히 고지하지 않음

### 적용한 해결책
1. CLAUDE.md에 "더미/테스트 데이터 사용 정책" 섹션 추가
2. 더미 데이터는 반드시 `[더미]` 접두사 + 가상의 이름 사용
3. 도메인 지식 필요한 내용은 임의 생성 금지

### 수정된 더미 데이터 예시
```json
{
  "name": "[더미] 테스트 조합 S-1",
  "coreChampions": [{ "name": "테스트챔피언1" }],
  "_notice": "⚠️ 이 데이터는 UI 테스트용 더미 데이터입니다."
}
```
