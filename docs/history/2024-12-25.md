## 구현 동작 방식

### 글쓰기 (`/board/write`)

```
┌─────────────────────────────────────────┐
│  페이지 로드                             │
├─────────────────────────────────────────┤
│  GET /api/admin/me 호출                  │
│  ├─ 200 OK → 관리자                      │
│  └─ 401 → 일반 사용자                    │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│  UI 분기                                 │
├─────────────────────────────────────────┤
│  관리자: "관리자로 작성합니다" 표시       │
│  일반: 닉네임/비밀번호 입력 폼 표시       │
└─────────────────────────────────────────┘
              ↓
┌─────────────────────────────────────────┐
│  POST /api/posts                         │
├─────────────────────────────────────────┤
│  서버에서 getAdminFromCookie() 확인      │
│  ├─ 관리자: author='관리자', is_admin=true │
│  └─ 일반: author=입력값, is_admin=false  │
└─────────────────────────────────────────┘
```

### 댓글 작성

동일한 방식으로 `POST /api/posts/:id/comments`에서 관리자 분기 처리

## 세션 4: 팀 코드 생성 기능 - 폐기

### 개요

TFT 인게임 팀 플래너에서 사용할 수 있는 팀 코드를 시뮬레이터 결과에서 생성하는 기능을 2회 시도했으나, **실제 게임에서 작동하지 않아 폐기**.

### 시도 내역

**1차 시도:**
- GitHub Gist 문서 기반 구현
- 포맷: `01` + 챔피언ID(20자리) + `TFTSet16`
- 결과: 실패 (실제 팀 코드는 32자리 이상, 다른 인코딩 방식)

**2차 시도:**
- Community Dragon 알파벳순 정렬 기반 챔피언 hex ID 매핑
- metatft 팀 코드 역분석 시도
- 결과: 실패 (게임 내에서 팀 코드 인식 안 됨)

### 폐기 사유

- TFT 팀 코드 공식 문서가 없음
- metatft 등 외부 사이트는 확장 포맷(`02`) 사용
- 기본 포맷(`01`)으로 생성한 코드가 게임에서 작동하지 않음
- 역분석에 필요한 시간 대비 효용 낮음

### 폐기된 파일

| 파일 | 조치 |
|------|------|
| `src/data/championTeamCodeMap.ts` | 삭제 |
| `docs/features/team-code.md` | 삭제 |
| `src/app/simulator/bronze/components/ResultCard.tsx` | 버튼 코드 제거 |
| `src/app/simulator/worldrune/components/ResultCard.tsx` | 버튼 코드 제거 |

### 결론

팀 코드 기능은 **구현 불가**로 판단하여 폐기. 추후 Riot Games 공식 API나 정확한 포맷 문서가 공개되면 재검토.

## 세션 6 실수 기록: 요청 범위 초과 변경

### 발생한 실수

**사용자 요청**: "다르킨을 지역 특성에서 제외해줘"

**AI가 실제로 한 것**: 다르킨 제거 + **타곤도 함께 제거** (요청받지 않음)

### 실수 원인 분석

1. **맥락 오해**: 이전 세션에서 REGION_SYMBOLS에서 타곤이 제거된 기록이 있었음 (타곤 상징이 게임 내 미존재)
2. **과잉 추론**: "타곤도 제외 대상"이라고 착각하여 요청 범위를 임의로 확대
3. **확인 미흡**: 변경 전 사용자에게 "타곤도 함께 제거할까요?"라고 확인하지 않음

### 문제점

- 사용자가 명시적으로 요청한 것만 변경해야 함
- AI가 "좋은 의도"로 추가 변경을 하면 예상치 못한 사이드 이펙트 발생 가능
- 사용자 신뢰 하락

### 수정 조치

- REGION_THRESHOLDS에 타곤 원복 (`"타곤": 1`)
- claude.md에 실수 방지 프로세스 추가

### 교훈

> **"사용자가 요청한 것만 정확히 변경한다. 추가 변경이 필요하다고 판단되면 반드시 먼저 확인받는다."**
